# bot_v4：声呐协作探索与空间请求

独立基于 bot_v3，保留局部避险、探索及分阶段繁殖。v1、v2、v3 不改动。
入口为 `main.py`，新增 `sonar.py`；官方 `helper.py` 保持不变，使用协议 3。

## 声呐策略

每个行动回合向 `(回合 + 蛇 ID) % 4` 对应方向发送一束声呐，四回合覆盖四个
发射方向。这样下一次行动收到的合计回波可以关联上一束的发射方向。
发射发生在行动之后，因此回波记录使用预计移动后的头部位置；分裂时位置不变。
若可见射线路径经过传送门或自身身体，则不将回波解释为某方向的风险。
未知传送门、折射及移动仍可能改变路径，方向信息始终只是软提示。

敌军回波增加短期方向风险，保留最多 6 回合，离开发射位置超过 3 格即丢弃。
最近 4 回合内收到敌军回波时暂停被动减员。没有回波不代表无敌人；回波数量
不计作敌蛇数量，也不用于证明全图优势。海带、友军等回波不会被转换为可通行地图。

## 消息与导航

| 类型 | 内容 | 有效年龄（回合） | 转发 |
|---|---|---:|---|
| 探测 | 无情报时的探测载荷 | 0 | 不转发 |
| 资源 | 实际观察且当前可达的食物位置、可达食物数量 | 16 | 最多一跳 |
| 拥挤 | 友方身体密度高且可达资源少的区域位置 | 8 | 不转发 |
| 空间请求 | 持续拥堵的长蛇位置、长度 | 4 | 不转发 |
| 敌情 | 可见敌蛇头位置、敌蛇 ID | 8 | 最多一跳 |

发送优先级为空间请求、拥挤报告、偶数回合的可见敌情、资源、待转发情报、探测。
每条蛇每回合只发送一个消息。转发保留原始来源、观察回合与内容，不延长寿命。
敌情按敌蛇 ID 去重，其他消息按类型和来源去重；重复或更旧消息不刷新记录。
直接看到资源位置已无食物时，立即删除该资源报告。

仅满足 `(自身 ID + 来源 ID + 资源 x + 资源 y) % 3 == 0` 的蛇跟随资源报告，
其他蛇继续自身探索。匹配多个目标时，综合环绕地图距离、情报年龄、资源数量选择。
附近拥挤/敌情报告降低该区域吸引力；资源目标靠近这些区域时暂不采纳。
目标导航复用候选移动的局部 BFS，再以环绕曼哈顿距离估计未知路程，因此不是
全图最短路，也不假设未知区域畅通。

本地攻击风险、出口、必要空间优先级最高；近处食物仍优先。无可达食物或
8 回合未增长时使用声呐导航提示，收到已验证的空间请求时也会尝试向外迁移。
所有实际候选移动必须经过本地视野确认。声呐不用于盲走或覆盖本地安全判断。

## 长蛇请求与短蛇让位

友方身体占可见格至少三分之一、且合法出口不超过一个，连续 3 个自身行动回合
满足时，长度至少 5 的蛇发出空间请求。接收端只接受附近（环绕曼哈顿距离不超过
4）且本地能确认发送者可见身体段数大于自己长度的请求；消息声称的长度也须更长。
确认后抑制主动分裂，并尝试远离请求位置，让出空间。

v4 比 v3 更谨慎：短蛇放弃应急分裂必须同时满足：

- v3 的局部压力条件持续至少 3 回合：我方总数至少 8，可见友蛇至少 4 且不少于
  可见敌蛇的 3 倍，友方身体密度至少三分之一，可达食物不超过 1。
- 自身长度不超过 4，有上述已验证的长蛇空间请求。
- 当前完全没有可验证的移动出口，最近 4 回合没有敌军回波。
- 当前回合与自身 ID 模 4 相同，并且自己是可见潜在短蛇响应者中 ID 最小者。

有路仍然移动，无请求仍保留应急自救，长蛇始终保留自救。不同视野之间无法
做到全队原子协调；选举和错峰降低同时减员风险，并不保证全图每次只淘汰一条。

## 协议、边界和开销

64 位消息布局为：8 位格式标记，3 位类型，1 位队伍，9 位观察回合，12 位来源 ID，
9 位 x，9 位 y，12 位值（长度/数量/敌方 ID），1 位转发标记。
坐标支持 0–511，ID 支持 0–4095，回合支持 0–511；不能编码时跳过发送，不截断身份
或坐标。长度与数量按 4095 封顶。格式标记及队伍字段只是过滤器，**不是身份认证**。
敌方可以截获或伪造消息；减员依赖本地压力与可见身体验证，不能仅由消息触发。

每回合最多处理 128 条输入消息，保留 64 条情报和 128 条已转发记录；风险表最多
4 项。声呐准备阶段新增一次局部 BFS，导航复用已有 BFS，不建立全图搜索。
v3 的最多 2048 格观察缓存和其他原有记录仍保留。

规则依据：[官方声呐文档](https://game.battlecode.au/docs/sonar)、
[协议 3](https://game.battlecode.au/docs/protocol)。
