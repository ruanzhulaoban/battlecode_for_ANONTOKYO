# bot_v3：探索、分阶段繁殖与拥挤减员

基于 bot_v2，增加贫瘠区域探索和拥挤时短蛇被动减员，保留原有移动避险。入口为 `main.py`。

## 判定与策略

只使用每条蛇可见的 7×7 区域，不将未知区域当作空地，也不宣称掌握整张地图。
静态空旷度 = 1 − 可见海带边数量 / 可见边数量（各格子的四个方向）。
当前空旷度至少 80%，且指数平滑值至少 85% 时，采用空旷区域策略。
平滑值每回合更新为 `旧值 × 0.75 + 当前值 × 0.25`；新蛇从自身视野初始化。

| 回合 | 空旷区域分裂长度门槛 | 其他区域门槛 | 空旷/其他区域每条蛇预留面积 |
|---|---:|---:|---:|
| 1–120 | 4 | 6 | 24 / 48 |
| 121–300 | 6 | 8 | 32 / 64 |
| 301–449 | 8 | 10 | 48 / 80 |
| 450–500 | 停止主动分裂 | 停止主动分裂 | — |

主动分裂固定生成长度 2 的子蛇，母蛇保留其余身体。目标数量为地图面积除以
预留面积，至少 2 条，最多为规则允许的队伍上限。数量读取官方队伍计数。
这些是初始可调参数，不是对所有地图都最优的结论。

额外检查：同一母蛇主动分裂间隔至少 4 回合；可见格至少 16 个；蛇身占格不超过
25%；完整身体和尾端可确认；母蛇与新蛇头部均无可见的一/二步攻击风险，
各自有安全出口，可分配不同的出口格，并有至少 `max(12, 当前长度+4)` 格安全可达空间。
未知尾端或出口会推迟繁殖。被困时的应急分裂可绕过主动策略门槛，
但受下述短蛇被动减员条件限制。

## 贫瘠区域探索

记录最近观察过的地形位置（最多 2048 格），寻找可见区域中通往未知、
或至少 32 回合未观察区域的边界格。利用现有候选移动 BFS 计算到这些格子的
距离；没有此类边界时，寻找蛇头尚未访问过的格子。跨边界本身仍需下一回合
确认目的地安全，历史记录不作为动态占用信息，不盲走未知传送门。

没有可达食物时主动靠近探索边界。连续 8 回合没有长度增长时，探索可优先于
远处食物，并惩罚重复访问；移动后两步内可达的食物仍优先。所有探索评分均
排在攻击风险、出口和必要生存空间之后。持续航向只在这些条件相同时裁决。

## 拥挤与短蛇被动减员

官方协议仅提供我方总数量，**无法确认全图敌我数量比**。当前采用保守的局部
优势代理：我方总数至少 8，可见友蛇 ID 至少 4，且不少于可见敌蛇 ID 数的
3 倍（按身体 ID 去重，包含自己；视野无敌人不代表全图无敌人）。

当上述条件成立、友方身体占可见格至少三分之一、且蛇头当前可达食物不超过
1 个时，暂停主动繁殖。连续 3 个自身行动回合满足条件后，仅对长度不超过
4、且能确认邻居有更多可见身体段的短蛇，停止无路可走时的应急分裂。
这类蛇仍优先正常移动，只有完全没有可验证出口时才进入原有移动兜底，
接受自然淘汰以释放空间；不会牺牲仍有可验证出口的蛇。优势或压力条件消失立即重新计时，
长蛇仍保留分裂自救。阈值是待实战调优的参数，局部优势不保证全图领先。

## 航向稳定

移动评分优先比较攻击风险、安全出口、安全空间，再比较上述觅食/探索评分和重复访问次数。
这些条件相同时，优先沿当前朝向直行，再优先沿持续 8 回合的探索方向行进，
最后比较额外空间和固定的蛇 ID 方向顺序，取消原先随回合轮换的方向裁决。
探索方向到期时更新为当前朝向，不会主动强迫转弯；遇到障碍、敌人、
更近的食物或重复访问时，可以立即改变路线。
航向裁决本身只使用两个持久标量，不增加搜索。

## 开销

空旷度统计复用现有的边遍历，只增加两个持久标量（平滑值、上次主动分裂回合）。
繁殖安全检查最多增加两次局部 BFS，单次最多访问 49 个可见格；不搜索整张地图，
人口压力检查另加一次局部 BFS；探索目标距离复用移动 BFS，并增加最多 2048 格
的观察记录，不建立全图路径搜索。原有移动规划、访问记录和传送门记录仍然保留。
官方本地沙箱限制为每条蛇 48 MiB、每回合 100M points。

## 验证与运行

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\unswbc.exe run maps/big_empty.map bot_v3 bot_v2 --sandbox
```

测试覆盖前期分裂、阶段边界、海带密集区域、母蛇/子蛇遇敌、尾端不可见、
数量目标、冷却、拥挤、子蛇被困，以及 v1 的移动安全边界。

以下为继承自 v2 的历史验证，不代表 v3 的对战成绩。

2026-09-24 繁殖版本验证（加入航向稳定之前）：25 项单元测试通过。`big_empty.map` 上以 v2 为 A、v1 为 B，
官方沙箱完整运行 500 回合，v2 按总长度获胜。第 51 回合数量为 34:3，
第 101 回合为 64:3；v2 的 29,304 个行动回合中 points 均值 25.6M、
p99 28.7M、峰值 43.6M，低于 100M 上限。运行受 48 MiB 内存上限约束，
CLI 默认未输出内存峰值。回放：`replays/v2-open-sandbox.replay`。
单场结果说明前期扩张已生效，不能视为跨地图胜率结论。

航向稳定改动后：30 项测试通过，含连续 8 步直行、遇墙/敌人转向、
食物优先、探索方向裁决及避免重复访问。重新运行相同地图的官方沙箱对战，
v2 在 500 回合后按总长度获胜；28,732 个行动回合的 points 均值 25.5M、
p99 28.7M、峰值 43.7M，未报告内存超限。
新回放：`replays/v2-straight-open-sandbox.replay`。

2026-09-24 独立为 bot_v3 后：全项目 60 项单元测试通过（v1 8 项、v2 22 项、
v3 30 项）。新增测试覆盖无资源时
走向未知边界、长期缺粮、近处食物和障碍优先、观察记录容量，以及持续压力下
停止短蛇自救、数量不足/敌军接近/长蛇/缺少更长邻居时保留自救、有出口仍移动、
资源恢复清除压力。官方沙箱因临时目录访问被拒绝未能启动，提权运行未获授权；
本次尚无新对战结果，也未验证新增逻辑的沙箱 points 峰值。以上历史战绩不代表
当前版本的实战表现。
